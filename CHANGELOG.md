## 0.0.0.19 (Unreleased)

Dev preview build 19 (`build-sdk` stamps 0.0.0.19); the 1.1.0 release line
is unchanged until a `v1.1.0.19` tag. Design: knowledge/designs/alerts/unifi-nvr-storage-at-risk.md
in the factory.

- feat(adapter): build 19: **the NVR publishes Protect's own storage health, so the pak can alert on drive and volume health instead of fullness** (Protect fills the volume to its retention limit by design; devel reads 99.1 % and that is normal). Read from the bootstrap's `nvr.systemInfo.ustorage` (the same block UniFi OS serves at `/api/system`), present-only and verbatim, by the new `NvrStorageHealth` (no SDK dependency). Volume (the `primary` space, else the only non-root, non-swap one, as the UniFi OS storage page picks it): `Storage|volume_health` (`health`, `atrisk`, `failed`), `Storage|volume_issues` (`reasons[]` as `type:level` in Protect's order, `none` for an empty list), `Storage|volume_action`, `Storage|volume_device`. Drives (`disks[]`, published only when every entry has a `state` and `slot`; empty bays, `nodisk`, are not drives): `Storage|drive_count`, `Storage|drives_not_healthy` (states the storage page colours orange or red, a `health` of `at_risk`/`broken`, or a risk `reason`; an unknown state counts, so it is surfaced, never passed), `Storage|drives_failed` (red only: `broken`, `faulty`, `not_support`), `Storage|unhealthy_drive_slot` / `Storage|unhealthy_drive_state` (the lowest-slot unhealthy drive, `none` when none), `Storage|drive_bad_sectors` (sum of `bad_sector`, only when every drive carries it). Also `Storage|hard_drive_state`, Protect's `nvr.hardDriveState` verbatim (vocabulary unknown, so informational). Flattened on the NVR, not per-drive child objects: consoles hold 1 to 7 bays, and the counts plus the first unhealthy slot and state carry an actionable alert. Vocabulary from the live devel bootstrap (UDM Pro, Protect 7.3.70, 2026-10-28) and the UniFi OS web UI's storage schema and status maps; redacted shape in knowledge/context/api-maps/unifi-network-api.md (Protect section) in the factory. Devel publishes `volume_health` `atrisk`, `volume_issues` `io_err:atrisk`, one drive in slot 1 `normal`, 0 bad sectors, `hard_drive_state` `hddNotCompatible` (checked offline against the captured bootstrap). Tests: NvrStorageHealthTest, tests/test_build19_storage_health.py.
- feat(adapter): build 19 (review B2, W1, W3, W2): **`Storage|volume_display_health`, the health Protect's storage page displays** (`healthy`, `atrisk`, `failed`; any other value verbatim, so it is surfaced), computed with the console UI's own rule: `health`/`healthy` display `healthy`, and a `primary` volume at risk only for `lacking_disk:atrisk` displays `healthy` only when it has no RAID block or `raid.had_most` is below `raid.expected` (an array that never had all its members). Protect's bootstrap trims the RAID block, so it is read from UniFi OS `/api/system` `ustorage.space[]` (new `UniFiApiClient.system()`, GET only, same session, once per cycle while Protect sends an NVR), matched by `device`. When it cannot be read the exception is not applied. An `atrisk` volume with no reasons list displays `atrisk`. A failed `/api/system` costs only the exception: a 401/403/429 is not asked again for 15 minutes (the `SysinfoGate` back-off, now named per call; one WARN), any other failure or a missing `ustorage` is logged at INFO once per streak. Devel: `atrisk` (`io_err:atrisk`, RAID expected 2, had most 1).
- fix(adapter): build 19 (review W4, W6, N1, N3): a `spare` drive with any `reason` counts as not healthy (the UI's `spare_at_risk`); during a two-member mirror resync on a healthy volume (action `repairing`, RAID expected 2, had most at least 2, one drive `normal` and one `repairing`) the `repairing` drive counts, and is named, as `initializing`, as the UI shows it, and only when the RAID block was read; a missing `ustorage`, recording volume or readable disk list, or an `atrisk` volume whose RAID block was not read, is logged at INFO once per streak per NVR; storage text is read only from JSON scalars (an object or list publishes nothing). Javadoc: `spare` is black in the UI, not green.
- feat(content): build 19: **NVR Storage At Risk** (UniFi NVR, Health badge, symptom-based severity) with five symptoms and one recommendation: Volume Failed (`volume_display_health` = `failed`, Critical), Volume At Risk (= `atrisk`, Warning), Volume Health Unrecognised (not `^(healthy|atrisk|failed)$`, Warning), Drive Failed (`drives_failed` > 0, Critical), Drive Not Healthy (`drives_not_healthy` > 0, Warning); recommendation UniFi Investigate NVR Storage At Risk. Protect's verdict only: no fullness, no bad-sector threshold of the pak's own, no raw `io_err` match (review B1, B3). The pak now bundles 9 alerts, 19 symptoms and 7 recommendations. <!-- TODO(build 19): confirm these counts after the content authors finish. -->
